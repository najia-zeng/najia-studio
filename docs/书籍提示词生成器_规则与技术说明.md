# 书籍提示词生成器 · 实现说明与规则全文

> 生成时间：2026-11-22  
> 对应文件：`assets/kcb.js`（线上版本 commit 72915fc）

---

## 一、它不是一个 Markdown 文档

这个工具是一个纯前端网页，跑在浏览器里。规则不是放在 Markdown 里读的，而是作为一个字符串常量写在 JS 文件里，每次请求时拼进发给模型的 prompt。

**为什么用 JS 常量而不是单独的文件：**

- 网页直接打开就能用，不需要后端读文件
- 拼进 prompt 时零延迟
- 缺点：改规则要改代码，所以我给你这份文档，规则全文在这里，你可以直接看和改

---

## 二、文件结构

```
kuociq-book.html          24 行的空壳，只负责加载资源
assets/kcb.css            样式（含四个风格按钮）
assets/kcb.pre.js         DOM 模板（页面长什么样）
assets/kcb.js             全部逻辑 + 规则常量（核心）
```

这是你之前做的"外壳化"架构：HTML 里看不到内容，所有代码都在 assets 下，别人右键查看源码只能看到一个空壳。

## 三、规则是怎么嵌进去的

`kcb.js` 里有一个超长字符串常量：

```javascript
var B = "【书籍/笔记本类专用规则 · 必须严格遵守】\n零、最高原则...";
```

每次用户点生成，代码做的是这件事：

```javascript
// 伪代码，实际是压缩过的单行
prompt = 用户上传的图片 + 用户的补充说明
       + "。请生成融合参考图风格的AI生图提示词。"
       + B                    // 十一章规则
       + STY[当前选中的风格]   // 四档风格之一
```

**顺序很关键。** 模型对后出现的内容权重更高，所以：

- 规则 B 在前，是基础约束
- 风格段在后，只做覆盖式微调

这也是为什么之前风格段能盖掉光影判断，我已经把风格段里所有光影相关的条目删掉了，并加了 5.6 明确禁止覆盖。

## 四、规则全文（十一章）

这部分就是 `var B` 的完整内容，一字不改。

```text
【书籍/笔记本类专用规则 · 必须严格遵守】

零、最高原则：转述参考图，不重新设计场景
0.1 本工具的任务是把参考图转述成提示词，不是凭空设计一个场景。
0.2 参考图里出现的元素，逐个写进提示词，一个不漏。有5个道具就写5个，不设数量上限。
0.3 参考图里没有的元素，一个不加。不要因为"通常场景里应该有"就补上。
0.4 构图、机位、景别、光影、道具数量，全部以参考图实际为准。
0.5 主体（书或笔记本）是唯一需要添加的元素。从参考图里选最合理的承托面放置，优先选画面里最显著的平面、光线最好的位置、不与现有道具冲突的位置。参考图里没有明显承托面时，选前景的平面。
0.6 参考图里已有同类主体时，按它在图里的实际位置和姿态描述，不要挪动。
0.7 参考图元素过多时，优先写视觉最显著的3到5个，其余用"周围散落若干小物"概括。
0.8 后续所有规则与本节冲突时，以本节为准。

一、主体描述规则：
1.1 有书名的书籍（小说、商业书、画册、教材、工具书等）：主体开头写"《书名》+版本/装帧/品类"，例如"《纳瓦尔宝典》中文简体版精装实体书"。书名必须加书名号。
1.2 无书名的本册（笔记本、手账、速写本、日程本、线圈本等）：只写品类与规格，例如"A5硬面横线笔记本""B5软皮日程本"。
1.3 书名只出现一次。严禁描述封面上的具体文字内容，用"标题色块""分色段""纹理区域""书名框"指代。严禁"印有文字""大标题文字""副标题文字"这类表述，写了AI会造出乱码字符。
1.4 必须写装帧类型：精装 / 平装 / 锁线装 / 线圈装 / 胶装 / 骑马钉。
1.5 必须写封面工艺，从下面词库里选1到2项，描述的是质感不是内容：
    表面工艺：烫金、烫银、烫彩箔、压凹、击凸、局部UV光油、丝网印刷、覆哑膜、覆亮膜
    装帧结构：布面精装、纸面精装、皮面、圆背书脊、平背书脊、露书脊锁线、毛边本、书口刷色、护封加内封、函套
    示例："藏青色布面精装，书脊烫金，封面压凹书名框"
1.6 整段2到3句，写清品类、规格、装帧、工艺、主色。

二、场景与空间规则（从主体出发，一层一层往外推）：
2.1 用"主体→承托面→环境"的链式结构，一段话写完。严禁把主体、桌面、沙发、道具各写一句并列成清单。清单式写法会让AI把元素各自生成再拼贴，比例必然失真。
2.2 按参考图实际构图写，不套固定句式。参考图怎么摆就怎么写：
    - 桌子只露一角：写"桌面只露出画面右下角一部分，边缘被画面裁切"
    - 窗只露一半：写"窗只露出左半边，右侧被画面边缘裁切"
    - 道具散落各处：写"桌面左侧有X，右前方有Y，后方有Z"
    - 承托面在画面边缘：写"承托面从画面右边缘延伸进来"
    - 道具被裁切：写"画面左边缘的杯子只露出半个"
    以下句式只作参考，不强制套用：
    "主体平放在【承托面】的【方位】；承托面后方是【环境元素】，处于背景虚化层；左侧是【环境元素】，右侧是【环境元素】；承托面【位置】有【道具】。"
2.3 必须写物理接触关系：主体底部与承托面完全贴合，有轻微接触投影，承托面有主体的柔和倒影。不写接触关系，AI会把产品和场景画成两张图贴在一起，出现悬浮感。
2.4 尺度写参考图里的实际占比，不写绝对数值。生图模型没有三维坐标系，识别不了具体的长度数值，写了等于没写。
    - 主体在参考图里占承托面多大，就写多大
    - 道具在参考图里是大是小，照实写，不要统一成"小物"
    - 参考图里道具比主体大（如花瓶高于书），照实写，不要强行缩小
    - 前后层级按参考图实际层序写：哪些在主体前方、哪些在后方、哪些被裁切
2.5 视觉层级与景深：主体最清晰锐利，承托面次清晰，环境元素柔和虚化。景深关系必须写出来，否则画面会平。
2.6 若上传的是白底电商图（产品占画面很大），严禁照搬该比例，一律按本节规则重新构图。

三、景别判断（用于标注输出字段，不限制元素数量）：
3.1 景别是判断结果，不是设计要求。先看参考图属于哪一档，把名字填进输出字段，然后按参考图实际元素数量写描述。不因为景别是"中景"就删掉图里的道具。
3.2 判断依据：
    特写：主体占画面纵向四分之三以上，只能看到主体局部，看不到完整承托面
    近景：主体完整，占纵向二分之一到三分之二，承托面只露出局部
    中景：能看完整承托面，主体占纵向三分之一到二分之一
    全景：能看到环境（沙发、窗、墙、地面），主体占纵向四分之一到三分之一
3.3 景别与元素数量不自洽时（例如判定为中景但参考图里道具很多），以参考图为准，景别字段如实标注即可，不得为了符合景别而删减元素。
3.4 参考图里主体只露局部（如只看到书的一角），景别按特写标注，描述按实际可见范围写，不要补全成完整的书。
3.5 参考图里没有承托面（书直接放在地面上），按实际写"主体直接置于地面"，不要虚构一个桌子。

四、光影规则（按摄影师布光逻辑写，六项齐全）：
4.1 先判断原图光质再写，判断依据是看阴影边缘：
    - 边缘锐利清晰、明暗分界明显 = 硬光
    - 边缘逐渐消失、有渐变过渡 = 柔光
    - 几乎看不到阴影、无方向性 = 漫射光
    必须按原图实际光质写，严禁一律写柔光。原图是硬光就写硬光。
4.2 光影段固定写这六项：
    （1）主光方向：从左前上方 / 从右侧正侧面 / 侧逆方向 / 正逆光 / 从正上方
    （2）光质：硬光 / 柔光 / 漫射光
    （3）主光高度：从偏高位斜下来 / 与主体几乎平齐 / 从低位往上打
    （4）明暗反差：低反差（阴影很浅，暗部细节完整）/ 中反差（明暗分界清晰但不生硬，暗部保留层次）/ 高反差（亮部明亮、暗部深暗，交界明确，暗部细节减少）
    （5）过渡特征：锐利生硬 / 渐变柔和 / 几乎无阴影
    （6）辅光与轮廓光：有无、强弱、勾哪个边
4.3 光质效果对照：
    - 硬光：阴影边缘锐利，反差大，质感突出，适合皮革、木纹、布纹、有纹理的封面
    - 柔光：阴影渐变，反差低，适合哑光纸、大面积纯色封面
    - 漫射光：几乎无阴影，无方向，色彩饱和度低
4.4 明暗反差按画面结果描述，不写任何比值数字。低反差用于白底电商和哑光浅色封面，中反差是通用商业摄影的基准，高反差用于强调纹理、体积和封面工艺细节。
4.5 严禁描述任何摄影棚器材（灯具支架、柔光设备、反光设备、闪光设备）。写了器材名，AI会把器材当成画面里的物件画出来。画面内的实际灯具（台灯、壁灯、落地灯、蜡烛）不受此限，按 4.8 处理。
4.6 纸面质感靠光不靠滤镜：侧逆光斜擦过封面时，哑光纸有细腻的漫反射微光泽，布面精装纤维有方向性起伏，书口有细微纸张分层。这是书籍高级感的来源，必须写进光影段。
4.7 调性按品类定：文学小说写"沉静、有呼吸感、克制"；艺术画册写"高级、留白、策展感"；商业书写"利落、可信、专业"；笔记本手账写"轻松、日常、亲近"。

4.8 环境里有灯具时（台灯、壁灯、落地灯、蜡烛等），光影段必须把它写成画内光源，只描述它产生的光效，绝不重复它的身份。
    正确写法："台灯罩内透出暖调微光，在桌面右侧形成一小片暖色光斑，灯罩边缘有柔和光晕"
    错误写法："辅光为右侧台灯"——模型会去画那个灯，而不是画它发出的光
    若参考图里的灯没有点亮，不要写它发光，只把它作为画面里的一个物件描述。
4.9 参考图里的灯具只露出局部时，按实际可见范围写，不要补全：
    "画面左边缘露出一小截灯罩，边缘被画面裁切"
    严禁写成"左侧有一盏完整的落地灯"。
五、质感基准（若用户已选择画面风格，以风格段为准；本节仅在未指定风格时作为兜底）：
5.1 未指定风格时，默认细腻胶片质感。
5.2 颗粒极轻，均匀分布，可见但不遮细节。
5.3 封面颜色必须准确，暖调只作用于环境光层面，不能改变封面本色。
5.4 画质段固定写"细腻质感，极细颗粒，解析力足够还原材质，封面与环境材质的肌理清晰可辨，织物有绒感和纤维起伏，木面有纹理走向，高光柔和不过曝，暗部有层次"。
5.5 补充说明里的额外风格要求与本节叠加时，以补充说明为准。
5.6 风格段只调整色彩、颗粒、质感与画质，不改变光影段的主光方向、光质和明暗反差。光影段永远以原图实际光质为准，风格段不得覆盖。

六、材质与肌理规则（决定画面真实感）：
6.1 场景里的每个环境元素和道具都必须写材质，不能只写颜色和形状。
6.2 材质必须写表面微结构，不能只写材质名：
    - 棉麻布艺：经纬织纹清晰，表面有细密纤维起伏，坐垫有使用后的轻微凹陷和褶皱
    - 绒布：短绒有方向性，不同角度呈现深浅变化，边缘有细微绒毛
    - 针织织物：粗棒针线圈疏密略有差异，针脚不完全整齐，边缘有轻微卷曲
    - 实木：木纹走向自然，有导管孔和轻微色差，表面是哑光而非镜面反光
    - 陶瓷：釉面有细微凹凸，高光是柔和扩散的而非完美圆点
    - 玻璃：有轻微反射和指纹痕迹，不是完全透明
6.3 真实感来自不完美，画面里至少写一处轻微的使用痕迹或自然瑕疵：布面褶皱、边缘轻微变形、木面细小划痕、表面薄尘、摆放角度不完全正。
6.4 光影必须配合材质：侧光或侧逆光斜擦过粗糙表面时，会在纹理凹陷处形成细微明暗变化。这是肌理可见的前提，平光会把一切照得光滑。
6.5 严禁把环境元素画成样板间或产品精修图的效果。真实空间里布面有褶皱、木面有纹理、金属有使用痕迹。

七、文字与负向词规则：
7.1 正向描述里，封面只写"封面有完整的图文排版结构""书名区清晰"这类结构描述，不要写"文字""字样""字体""文字区"这些词，也不要描述具体内容。
7.2 负向词只写一句，列的是错误形态，不是物件名称：
    "画面中不出现伪文字、乱码字符、错别字、水印、标签、卖点文案、参数表、电商详情页排版元素、塑料感、过度光滑、蜡质表面、样板间效果。"
7.3 不要在负向词里写"除封面外无文字"这类条件句。模型不理解"除……外"的逻辑，看到"文字"两个字就会在画面各处画字。
7.4 严禁在负向词里列举任何具体物件名称。生图模型对负向词处理不干净，提到什么就可能画出什么。
八、机位与角度规则（必须从原图判断，严禁套模板）：
8.1 判断依据：看书在画面里的形状，以及书脊能看到多少
    - 封面呈规整矩形、书脊几乎看不到 = 正对平视
    - 封面呈规整矩形、同时看到一条书脊 = 斜侧45度平视
    - 封面呈梯形（近大远小）、看得到桌面 = 俯拍
    - 看到书脊侧面偏多、封面有压缩 = 斜侧俯拍
    - 看得到书底或封面下缘、看不到桌面 = 仰拍
    - 封面呈菱形、书脊和顶边同时可见 = 高位斜俯
8.2 机位段固定写三项，每项都要有具体方位：
    （1）相机高度：高于主体俯视 / 与主体平齐 / 低于主体仰视
    （2）相机方位：正对封面 / 斜侧45度 / 正对书脊 / 从正上方垂直俯拍
    （3）画面透视：无明显透视变形 / 有轻微透视收缩 / 有明显近大远小
8.3 机位必须与景别自洽：
    - 特写、近景：机位与主体平齐或略高，不俯拍
    - 中景：可以是平视或45度俯视
    - 全景：通常45度俯视或平视，机位高度略高于承托面
8.4 若原图是白底电商图（正对平视、无透视），转成场景图时改为斜侧45度俯视。正对平视塞不进场景元素，硬塞会导致比例失真。
8.5 严禁写"略微仰拍""专业机位""镜头正对书面封面"这类无信息量的词。这三项必须各自写清具体方位，不能互相矛盾。

九、真实感规则（消除AI味，这是最终效果的关键）：
9.1 真实照片是不完美的，AI生成的图太完美所以假。画质段和描述里必须体现这些特征：
    - 轻微噪点：画面有极轻微的自然噪点，不是纯净无瑕的数字画面
    - 高光轻微溢出：最亮处有轻微溢出和光晕，不是完美渐变
    - 边缘轻微软化：画面四角比中心略暗，边缘清晰度略低于中心
    - 暗部带环境色：暗部不是纯黑，带一点环境反射色
    - 对焦不完全均匀：焦点处清晰，前后有自然过渡，不是全画面锐利
9.2 材质必须写不完美：布有褶皱和压痕、木有纹理和色差、陶有釉面起伏、玻璃有反光和指纹痕迹。
9.3 光影必须写不平：侧光斜擦过表面，纹理凹陷处有明暗变化。平光会把一切照得光滑，这是AI味的主要来源。
9.4 严禁写"完美""无瑕""精修""样板间""产品图级""商业级精修"这类词。
9.5 整体基调写成"真实环境里的随手拍"，不要写成"商业产品摄影"。除非用户明确要求商业广告风格。

十、输出结构：
类型 / 景别 / 主体 / 场景与空间 / 机位与角度 / 风格 / 色彩 / 调性 / 光影 / 画质 / 负向词

十一、元指令（必须原样作为提示词最后一句输出）：
"严格按参考图的实际构图转述：元素位置、数量、裁切范围、前后层序、光位光质全部照图写，不增不减不重新设计；主体与承托面的比例符合真实物理世界，不放大主体、不压缩承托物。"
```

## 五、四档风格全文

### 胶片（film）

```text
【画面风格：胶片质感】（只调整色彩与质感，光影以原图为准）
- 颗粒：极细胶片颗粒，均匀分布，可见但不抢细节
- 饱和度：整体降低约15%，色彩温润不刺眼
- 色调：暖调偏黄，白平衡略偏暖，接近柯达Portra 400
- 高光：滚降自然，不过曝
- 暗部：有层次不死黑，暗部带一点暖色
- 画质：胶片质感，细节清晰但不锐利刺眼
- 风格排除项：过度噪点、颗粒粗糙、数码锐利感、高饱和、冷调偏蓝
```

### 数码（digital）

```text
【画面风格：数码干净】（只调整色彩与质感，光影以原图为准）
- 颗粒：无颗粒、无噪点，画面纯净
- 饱和度：准确还原，不夸张不偏色
- 色调：中性白平衡，颜色准确
- 高光：干净利落，不溢出、不晕光
- 暗部：通透，细节完整
- 画质：高解析力，边缘清晰，细节完整
- 风格排除项：颗粒、噪点、色偏、暖调过重、柔焦、雾感
```

### 自然生活感（natural）

```text
【画面风格：自然生活感】（只调整色彩与质感，光影以原图为准）
- 色调：明亮通透，略偏暖，接近清晨或午后
- 饱和：自然真实，不夸张
- 质感：生活化有呼吸感，不像棚拍
- 画质：清晰自然，细节丰富
- 风格排除项：棚拍感、过曝死白、色温过冷
```

### 暗调高级感（dark）

```text
【画面风格：暗调高级感】（只调整色彩与质感，光影以原图为准）
- 背景：深色（深灰/墨绿/深棕），大面积压暗
- 高光：局部高光勾出封面边缘与纸面质感
- 暗部：大面积深暗但有细节，不死黑
- 色调：偏冷或中性，高级感
- 画质：锐利，材质质感突出
- 风格排除项：明亮背景、均匀照明、灰蒙蒙、发灰"
```

## 六、为什么要这么写（设计原理）

这份规则不是拍脑袋写的，每一条背后都有一次踩坑。

### 1. 提什么，画什么

早期负向词里写了"摄影灯、柔光箱、反光板"，结果生成图里真的出现了柔光箱和反光板。

**生图模型对负向词处理不干净**，它看到"柔光箱"三个字就激活了柔光箱的图像特征，不管前面有没有"不要"。

结论：负向词只列错误形态（伪文字、乱码、水印），不列物件名。

### 2. 技术参数是废词

写过"光比 3:1""主光 45 度""桌面直径 45cm"，模型完全不懂。

它没有三维坐标系，也没有测光表的概念。训练数据里的图片描述不会出现这些数字，所以它们和视觉特征之间没有映射。

**判断标准：这个说法能不能在成片上肉眼验证。** 能验证的是真描述，不能验证的是噪音。

### 3. 示例污染

规则里给了一个柔光的例子"光源面积大、边缘过渡柔和"，结果不管你上传硬光还是柔光，它都写"柔和"。

**给一个示例，模型就只会那一个答案。**

结论：不给答案模板，给判断方法。现在的 4.1 是教它"看阴影边缘判断光质"，不是告诉它"光应该是柔的"。

### 4. 层级冲突

风格段曾经写了"光源：窗边侧光""阴影：柔和但有方向"，直接指定了光源。选"自然光"时，不管你上传什么图，光影都会被写成窗边柔光。

结论：规则分层，各管各的。光影段管光位光质，风格段只管色彩颗粒，加 5.6 明确边界。

### 5. 清单 vs 链式

早期结构是"主体一段、场景一段、道具一段"的平铺清单，AI 会各自生成再拼贴，比例必然失真。

结论：改成"主体→承托面→环境"的链式结构，每一层都以主体为尺度基准。

### 6. 占比规则会压扁桌子

写过"书占画面 70%-85%、要看到完整桌面和沙发窗景"，物理上做不到，AI 只能压缩桌子来满足。

### 7. 平光会把一切照光滑

生成的图里沙发没有织纹、木桌像刷漆，因为光太平，纹理凹陷处没有明暗变化。

结论：材质要写表面微结构，光影要侧光斜擦，两者配合纹理才出得来。

### 8. 【最新】设计 vs 转述 —— 架构级的方向错误

之前所有规则都是"从零设计一个场景"的逻辑：规定主体占多大、几个道具、什么景别、承托面要完整。

**但实际任务是"把一张已经存在的参考图转述成提示词"。**

两种任务的规则方向完全相反：

| 设计逻辑（错） | 转述逻辑（对） |

|---|---|

| 中景只能 1-2 个道具 | 图里有几个写几个 |

| 必须看完整承托面 | 桌子只露一角就写露一角 |

| 灯要详细描述 | 灯只露一截就写露一截 |

| 主体占承托面一半 | 图里怎么摆就怎么写 |

结果：参考图里有 5 个道具，规则只让写 2 个，AI 只能删；桌子只露一角，规则要求完整，AI 只能虚构。

**结论：新增"零、最高原则"，明确规定任务是转述不是设计，后续所有规则与它冲突时以它为准。同时删掉所有元素预算数字。**

## 七、怎么改

### 改规则文字

直接改 `assets/kcb.js` 里 `var B="..."` 的内容。注意：

- 文件里中文是 `\uXXXX` 转义格式，肉眼不可读
- 直接手改容易破坏转义，建议用脚本解码 → 修改 → 重新编码

### 改风格参数

改 `STY` 对象里对应那一段，四档分别是 `film` / `digital` / `natural` / `dark`。

### 改了之后

```bash
git add assets/kcb.js
git commit -m "说明"
git push origin main
```

推送后约 20 秒线上生效，刷新固定链接即可。
